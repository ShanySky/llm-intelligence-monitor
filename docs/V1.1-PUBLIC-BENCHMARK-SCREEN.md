## 下一阶段：先验证环境，不急着调用模型

1. **批量零模型费用预检**：对 A 组任务使用官方 Dockerfile / 测试脚本，固定原始 commit；基线 F2P 应失败，应用官方修复后 F2P 应通过，P2P 不回归。
2. 复用官方评测及缓存环境，**模型不可读取 gold.patch、test.patch、tests.json 的答案部分**。不要误将带解答的官方文件放进 agent 工作区。不得用关键词匹配或手调分值。
3. 记录镜像是否能拉取/构建、依赖安装、测试时间/CPU 内存。仅在原版行为和评测链路通过后才给任务 `environment_ready`。
4. 同项目尽量共享已构建镜像。预构建耗时与 agent 的单题时间分开报告；超时、下载失败、依赖故障均记为 **无效样本**，绝不计为模型做错。
5. 阶段二才每轮运行 Luna High 3–5 道有效题；Luna 高分归 Coverage，低分必须先检查环境和预算。模型分数采用官方每题通过/失败、综合解决率，不因目标 60 分而变更题目/评分。
6. 复测稳定后才引入 Sol Medium / High；X High 与 Astra 延后。任何分数都是测试结果，**不承诺必然达到目标区间**。

## 风险与止损

- 官方题目集中在 2017–2024 年，存在公开数据污染可能；需要单独记录，不把成绩包装成全新未见任务的能力指标。
- Vue 官方 Dockerfile 包含 Node 20、pnpm 与浏览器；Druid/Lucene/Lombok 构建可能更重，先排后。不能在未测运行时间前说这些任务满足 10 分钟上限。
- 现有 `light-agent-runner` 服务于小工作区，SWE-bench 是原始仓库 + patch 验证；应优先调用成熟官方执行器与原版测试，**只做最薄的结果适配**，不要把整个公开仓库改造成新微型题。
- 若官方镜像或测试难以低成本复现，切换已有 Multi-SWE-bench Flash/Mini 或其他小环境题源，不无限制排障。
- 不恢复日测；不因为修改配置/文档触发付费 Workflow；本阶段无模型调用。
