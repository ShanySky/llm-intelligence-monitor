在 V1.1 Beta 发布后，**只验证最小充分的档位区分信号**，而不重新开始盲目筛题。

- 原版官方问题：`vuejs__core-11899`，SWE-bench Multilingual 固定源码。
- 历史先验：Sol High 在原题上官方评分为 0，Luna High 为 0，但不同工具/预算限制之间不能直接做长期对比；选它是为了避免前一批测试的满分天花板。
- 同一模型 `gpt-6.1-sol`，同一题目及固定 Harness：Medium / High / X High 各一次。
- 每档 Agent 最多 30 responses、40 shell、540 秒、20 万累计输入 Token（检查后再决定是否继续下次调用），不重复抽样。独立评分器照原版官方测试验证。
- 独立历史分支 `v11-sol-effort-results`；记录样本有效性、0/100 官方结果、输入/输出/思考 Token、响应轮次及实际用时。
- 存在超时、预算上限或基础设施失败，分数为空，不得记零分；单道题单次运行只可作为待复验信号，不能断言档位强弱。
- 只复用现有 Workflow，原 V1.1 默认的免费 `v1.1-report` 不变，V1 保留。
- 本轮禁止自动追加第二题、Sol XHigh 重试、Astra 或额外工作流次数；无信号及时停止。

## First result, and the only remaining final complementary task

Official model run [#37880288321](https://github.com/ShanySky/llm-intelligence-monitor/actions/runs/37880288321) returned valid scores **Medium 0, High 0, X High 0** on Vue #11899. Input tokens respectively 35268, 110410, 120007 and agent seconds 80,178,260. Thus there was no observed quality separation despite higher cost.

Exactly one more existing original task, `vuejs__core-11589`, is used as the complementary case (historical Sol High 100/100, Luna High 0/100); it passed network-none original reference tests. Its Medium / High / X High each get one trial on the same original issue, fixed task-specific scoring and identical 200k input-token cap, 30 calls, 40 shells, 540s deadline. This is the **final paid batch** for this small study; do not automatically add further cases or repeat results if inconclusive.

### 评分边界修正

首轮代码的 20 万累计输入 Token 预算是调用前检查：它不能预知一次 Responses API 返回会占多少 Token，因此 **不是 API 账单硬限制**。旧 Runner 在模型正常完成后只依赖是否准备发起下一次调用来判断预算状态，导致第二题 X High 最终输入 204,078，却仍在原始报告计为有效 100；High 208,678 因准备进入下一轮而触发限制。

现在修正为：所有具有 200k 限制的样本，如果最终累计输入 **超过 200,000**，无论是否正常结束都标记为 budget-confounded，质量分 NULL。严格预算不能在 API 级别提前保证，后续必须按此约束如实报告。

**历史原始结果文件不改写**；另存独立的 [两题六样本严格同预算汇总](https://github.com/ShanySky/llm-intelligence-monitor/blob/v11-sol-effort-results/effort/study-summary.md)，说明口径变更原因和原始官方测试结果。
