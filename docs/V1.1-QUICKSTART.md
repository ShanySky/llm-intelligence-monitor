# V1.1 公开工程能力评测测试版：快速开始

## 可用范围

V1.1 在 V1 `v0.1.0-beta.1` 的手动 Core 评测之外，提供**原版公开 Java/Vue/JS 工程题的实测证据报告**，并增加**按需单题、单模型、单档位**的工程任务测试。免费刷新历史报告是默认行为，**不会自动调用大模型**。

已完成官方任务准入的案例来自 [SWE-bench Multilingual](https://github.com/SWE-bench/swe-bench-multilingual-tasks) 固定源码版本，评分直接采用官方测试。所有 GitHub Actions 使用仓库中已有的 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` Secrets；模型为用户配置的 API 模型，不是 ChatGPT 订阅额度。

## 入口一：免费刷新 V1.1 报告（推荐先用）

1. 进入 [Actions → Frontier batch candidate screen](https://github.com/ShanySky/llm-intelligence-monitor/actions/workflows/frontier-batch-screen.yml)。
2. 点击 **Run workflow**，选择分支 `v1.1-discrimination-upgrade`（合并到 main 后可直接使用 main）。
3. `profile` 选择 **`v1.1-report`**（默认），运行。不会调用模型，不会跑旧的付费筛选矩阵。
4. Actions → Summary 可看中文报告，或读取 [V1.1 最新持久化报告](https://github.com/ShanySky/llm-intelligence-monitor/blob/v11-release-results/v11-release/latest.md)。JSON [在此](https://github.com/ShanySky/llm-intelligence-monitor/blob/v11-release-results/v11-release/latest.json)，运行历史位于 `v11-release-results:v11-release/runs/<run_id>.json`。

报告明确列出有效/无效成绩，模型/档位、耗时与 Token，并标识 Coverage、仅单次模型差异、未验证的 Effort 档位。**报告是历史真实测试结果的可信聚合，不是一次新模型测评。**

## 入口二：付费手动测试某一道公开工程题

同一个 Workflow 中，**主动**把 `profile` 改成 `v1.1-task`，然后选择：

- `case_id`：一项官方案例（已有准入白名单；不能添加未验证的任务）；
- `model_id`：`gpt-6-luna` 或 `gpt-6.1-sol`；
- `effort`：`medium`、`high` 或 `xhigh`。

每次只运行 **一道题 × 一个模型 × 一个档位**，无矩阵扩散、无自动重复。Agent 最多 30 Responses / 40 Shell / 540 秒，并设置累计输入 Token 保护上限 **200,000**。脚本会确认原始版本、在需要时联网准备本地测试依赖、检查源码不变、断开模型容器网络后运行 Agent；模型退出后才在另一个独立容器应用模型补丁、运行官方评分。

结果保留在该次 Actions 的 `v11-task-...` Artifact，并持久化至 [v11-public-manual-results 分支](https://github.com/ShanySky/llm-intelligence-monitor/tree/v11-public-manual-results) 的 `v11-manual/latest.json`、`latest.md` 及 `runs/<run_id>.json`。该结果分支只有首次手动运行后才会出现。

若模型超时、工具/Token 预算用尽、评测依赖或环境失败，质量分为 **NULL/无效**，不能按 0 分统计或与另一档位强行比较。每一行必须看 `data_complete` 与样本来源才可分析质量。

> 注意：手动 `v1.1-task` 会产生真实 API 费用，默认 `v1.1-report` 不产生模型调用。原 `frontier-batch` 研发模式保留在可选项中，但不是 V1.1 日常使用入口。

## 保持可用的 V1 功能

[原 V1 Core 快速开始](V1-QUICKSTART.md)：选择 [Final application benchmark validation](https://github.com/ShanySky/llm-intelligence-monitor/actions/workflows/application-final-validation.yml) 的 `v1-core`，继续运行两道模型区分核心题 × 四模型 High，结果独立写入 `application-v1-results`。与 V1.1 公开题报告互不覆盖。

## 已验证和待完善的边界

- **已有真实证据**：公开工程题的官方 baseline→gold 环境准入、Luna High 的多批次实际修复、Sol High 两道相同 Vue 题的单次对照、成本与完整性记录。
- **尚未确认**：同一模型 Medium / High / X High 能力差异、稳定的跨模型分差、完整 60/80/95 分能力梯度、Astra 上限。报告不会捏造这些。
- **V1.1 beta 验收层级**：免费证据报告及回归测试必须跑通；手动付费单题入口基于既有已实测 Harness，独立运行仍需按需观察，不为发布 beta 强行制造新的模型费用。
- 自动日测继续关闭；不新增无必要的定时 Workflow。公开任务与评分原版不变。

后续持续优化公开题库难度、跨档位验证与正式模型排序，不能阻碍现有可用 beta 的交付。
